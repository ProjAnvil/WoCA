# 2026-10-25

## OpenShell EE spec：个人开发者一条命令路径

- 用户新要求：个人开发者用**一个企业版 compose 文件**跑通 EE 沙箱，并且**至少在一台 container 内完成沙箱调用**。用户指定直接写进已有的 `deploy/selfhosted/docker-compose.full.yml`，不新建 compose 文件。
- 用户确认：完整 EE 链 + demo 容器形态；用脚本模型（无需模型 key）。
- 关键代码事实（已核对）：
  - `e2e/sandboxlab/docker-compose.yml` 是现成最小栈（pg、nacos、nacos-init、server、config、worker、fakesandbox、fakemodel、client）。租户 key 在 server 的 `:8090/api/tenant/users` 铸造，run 用 `POST /api/runs` + Bearer key。
  - worker 启动时调 `agentbuild.BuildAgent`，`config.BuildModel` 在 provider 为空时直接报错（`unknown provider`）。所以**模型设置必须先于 worker 存在**，开发者路径必须分阶段启动。
  - 企业版 compose 的 nacos-init 只发空 settings pack；server/worker 之间**没有共享工作区卷**（本次新增 `woca-workspaces` 卷修掉）。
  - 企业版防火墙把五个区两两 DROP，跨区只能靠双网卡服务在共享腿上通信。demo 容器需同时挂 `woca-app` 和 `woca-infra`。
  - 本机是 OrbStack 2.2.5，无 Docker Desktop；OpenShell 官方支持矩阵只列 Docker Desktop，OrbStack 未验证（需要 preflight 真实探测 + 可执行报错）。
