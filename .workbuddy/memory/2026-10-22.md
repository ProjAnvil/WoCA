## complab：组件集成测试套件（分支 feat/websearch-free-providers）

用户要求：「做好集成测试的套件，验证 woca 的各个组件都能工作，其中就有这个
web search 能用。例如调用组件搜索一个内容，能最终搜索到结果（不用管具体的通路情况）」。

照 `e2e/` 既有约定建了第三个套件 `e2e/complab/`（build tag `complab` + Makefile 目标，
与 netlab / sandboxlab 并列，但**不需要 docker**）：

- `make complab` / `make complab-offline`
- `harness_test.go`（helper）、`components_test.go`（免外网）、`websearch_test.go`（外网）、`README.md`
- 覆盖：工具注册表、文件工具链、Bash、设置库（含加密 secret 往返 + 重开持久化）、
  WebSearch、WebFetch、搜索→抓取组合。共 8 个组件测试。

### 三条设计取舍（值得复用）

1. **不断言是哪条通路在服役**。只要求「有结果 + 能解析出 URL」，服役 provider 只进日志。
   免费后端可用性随网络环境变，写死 provider 会在后端切换后误报。
2. **「不用管具体通路」另外做成断言**：`TestWebSearchSurvivesABlockedProvider` 把永远报
   `ErrRateLimited` 的假后端放链首，要求照样出结果且该后端只被调用 1 次（挑战页不重试）。
3. **没有外网 → skip；有外网但后端全被拦 → FAIL**。后者是真发现（数据中心 IP 下 DDG
   确定性失败），skip 掉就永远发现不了「默认后端在这套网络不可用」——那正是调研的 P0。

### 实测

住宅 IP 下 8/8 通过：搜索拿到 8 条（ddg-html 服役）、链首被拦后降级成功、
WebFetch 12,658 字节、搜索→抓取组合通过。离线模式下 4 pass + 4 skip。

### 踩到的点

- `settings.Open()` 会把主密钥写到 `WOCA_HOME`（默认 `~/.woca`）——测试里必须
  `t.Setenv("WOCA_HOME", t.TempDir())`，否则往用户家目录写东西。
- `e2e/lab/` 是 Playwright 用的后端宿主（`package main`），**不是**共享 helper 库，别去找复用点。
- 走 `tools.NewRegistry(dir)` + `reg.Get("WebSearch")` 是最贴近生产的调用方式；
  provider 级事件用 `websearch.SetEventHook` 采集（默认 router 没有 OnEvent）。
- 结果内容不做断言（搜索结果会变），只断言条数 > 0 与 URL 可解析。
