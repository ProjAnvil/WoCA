## openhuman 对比研究 + SWE-bench 参与评估

- 调研了 github.com/tinyhumansai/openhuman（Rust 单进程 agent harness，GPL-3.0，主打效率：68MB 内存 / 4.6k system prompt / RLM token 压缩 / Jev 工具搜索）。他们自建 openhuman-benchmarks 仓库，7-8 个 harness 在同一批 SWE-bench Verified 任务（swe-x86-1，10 实例）上同模型同容器逐调用计量，方法学公开可复现。
- woca 优势：executor 契约 v2 多后端沙箱（E2B/Daytona/SPACE）、企业多租户执行链、langgraph interrupt/resume、确定性权限门、Harbor/Terminal-Bench 评测已跑通。
- woca 差距：无 SWE-bench 代码；token 效率未审计（对方 4.6k vs 业界中位 7.7k）；工具规模大了之后无工具发现机制（对方 Jev 1215 工具 86.8% 命中）；无公开 benchmark 方法学；生态集成面窄。
- 结论：可以参与 SWE-bench，两条路。A) 给 openhuman-benchmarks 加 woca bundle+adapter（woca headless CLI 形态与 Claude Code 同模式，完美匹配其 meter proxy 架构）；B) 官方 SWE-bench Verified：写 runner 生成 predictions.jsonl（instance_id/model_name_or_path/model_patch），用官方 swebench.harness.run_evaluation 评分，先 10-20 实例校准。arm64 mac 需 --namespace ''。
- 关键复用资产：eval/woca_agent.py 证明 headless 驱动可行；make eval-binary 静态二进制；stream-json result envelope 是 Claude-Code 兼容格式（含 usage/cost）。
- 许可证注意：openhuman 是 GPL-3.0，只参考方法学不抄代码无传染；往他们仓库提交适配脚本需 GPL 兼容。

## 官方 5.x 对齐核查与修复（commit 3b533de）

- 需求方质疑耦合面后逐项核查（GitHub main/v5.0.1、PyPI 5.0.2、两版数据集），发现三处真 bug 并修复。
- 关键事实：swebench 5.x（2026-02 自包含化重构）要求 enriched 数据集 SWE-bench/SWE-bench_Verified（带 image/eval_script/log_parser 列），princeton-nlp 老版 15 列评分时 KeyError；官方镜像名内嵌在数据集 image 列且含版本段（如 sweb.eval.x86_64.astropy_1776_astropy-12907），不可从 instance_id 推导；5.x CLI 无 --namespace/--arch，--instance_ids 是 nargs="+" 空格分隔；空 patch 在 5.x 被过滤出报告分母（不是旧文档说的 empty_patch 计数）。
- 修复后耦合模型：评分=官方包原样运行（锁 5.0.2）、镜像名=直读数据集字段（官方改名自动跟随）、生成侧=官方设计明确不管。文件级契约只剩 predictions.jsonl 三字段。
- gold 预热收编为 `grade --gold`；generate 落 run.json manifest（记 swebench 版本）；52 项单测。
- 教训（通用）：对接外部工具时，硬编码命名约定和抄二手文档的 CLI 参数都是猜测性耦合；能直读权威源（数据集字段）就不要自己推导，CLI 契约要用测试固化。

## gold 预热实跑：10/10 resolved（commit a5d9578）

- 用户启动 OrbStack 后实跑。首跑全挂（10 个"image not found"），根因：官方 eval 镜像 amd64-only manifest，arm64 默认 docker pull 报 no matching manifest for linux/arm64，官方 harness 包装成"镜像不存在"。修法：build_pull_command 显式带 --platform linux/amd64，generate 逐实例预拉 + grade 新增预拉步骤（--skip-pull / --platform）。
- Docker Hub 未登录限速实测：前 3 个镜像 ~20MB/s，之后掉到 <2MB/s，sympy 镜像（~4GB）15min 超时三次被杀，靠并行补拉 + 层缓存续传收回。_pull_with_retry 定为 2400s/次 × 3 次（要容忍慢速下载，不能只防停滞）。教训：给慢速下载设超时要按"最坏吞吐 × 镜像体积"算，不是按"停滞"算。
- 最终结果：gold 预热 10/10 resolved、0 error、0 infra failure，OrbStack Rosetta 仿真下 10 实例 gold 评测仅 ~3 分钟（仿真没有想象中慢）。10 镜像留存本地，generate 直接复用不重拉。gold 报告归档 eval/results/swebench/warm/。
